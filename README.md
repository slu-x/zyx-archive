# Archive of Lay（张艺兴考古网站，Phase 0 技术测试版）

**正式测试网址：https://archiveoflay.com**（部署在香港 VPS 上，支持 HTTPS）

备用/对照网址：https://zyx-archive.syluxback.workers.dev（Cloudflare，国内访问不理想，仅作对照）

这份说明假设你**完全没有编程经验**。第一次出现的技术名词，都会在括号里简单解释。

如果你不想自己动手改文件，**最推荐的方式是：直接跟 Claude 或 Codex 说清楚你想加/改/删什么，让它帮你操作**（比如："帮我在『莲乎』这个分类里加一条链接，标题是 xxx，网址是 xxx"）。下面的手动步骤是给想自己动手、或者想看懂 AI 做了什么的人看的。

## 一、这是什么

这是一个"跨平台资料导航网站"：

- 打开网站 → 看到几个大分类（比如"综合""跨越平台"）
- 点进一个大分类 → 可能还有更细的小分类（比如"综合"里面的"舞台之神"），可以一层一层点下去
- 点到最后 → 看到具体的链接，或者一个"事件"（一次舞台/作品相关的多条链接合集）
- 点击链接 → 直接跳转到微博、抖音、B站、知乎……对应平台的原始页面

网站**不保存、不搬运**任何平台的内容，只是"指路牌"。网站顶部还有一个搜索框，可以直接搜标题/分类/平台名字。

## 二、文件夹里都是什么（不用全部看懂，知道去哪改就行）

```
zyx-archive/
├── index.html          ← 首页网页（不用改）
├── category.html        ← 分类页网页（不用改）
├── event.html           ← 事件详情页网页（不用改）
├── css/style.css        ← 网站样式/颜色（不用改）
├── js/                  ← 网站的运行逻辑（不用改）
├── assets/              ← 网站图标（不用改）
└── data/
    ├── nav.json          ← ⭐ 网站的"目录树"，决定有哪些分类、每个分类里有什么 ⭐
    ├── events/           ← ⭐ 存放"完整事件"（多条链接合集）的地方 ⭐
    │   ├── 2025-08-01-test-stage-a.json   ← 一个事件 = 一个文件
    │   └── ……
    └── events-bundle.json  ← 自动生成的汇总文件，不要手动改！改完 events/ 后要重新生成，见第十节
```

**日常维护资料，主要打交道的是 `data/nav.json` 和 `data/events/` 这两个地方，完全不用碰网页代码。**

## 三、核心概念：目录树（`data/nav.json`）

网站的分类结构就像一本书的目录，全部写在 `data/nav.json` 这一个文件里。打开它，你会看到类似这样的结构（这种格式叫 **JSON**，是一种非常通用的"数据记事本"格式）：

```json
{
  "tabs": [
    {
      "id": "comprehensive",
      "title": "综合",
      "color": "#D0CBE3",
      "children": [
        {
          "id": "stage-god",
          "title": "舞台之神",
          "children": [ ... 这里面还可以继续放更细的分类，或者具体内容 ... ]
        }
      ]
    }
  ]
}
```

- `tabs`：最外层的数组，里面每一项就是首页看到的一个大分类
- 每个"分类"节点有：`id`（英文/数字编号，网址里用得到，**同一个网站里不能重复**）、`title`（显示的中文名字）、可选的 `color`（这个分类卡片的颜色，只有大 tab 需要设置）、可选的 `intro`（会显示在这个分类页面最上面的一段引言文字，比如"莲乎"下面那句堂吉诃德语录）、`children`（里面装的东西，见下）
- `children` 数组里的每一项，**要么是继续嵌套的分类**（长得跟上面一样，可以一直往下嵌套），**要么是下面说的四种"具体内容"之一**

## 四、四种"具体内容"（叶子内容）

### 4.1 链接（`link`）—— 最常用

```json
{ "type": "link", "platform": "微博", "title": "工作室舞台照片", "url": "https://weibo.com/xxxxx" }
```

- `platform`：平台名称，决定链接前面小标签的颜色。目前有专属颜色的：`微博` `抖音` `小红书` `知乎` `贴吧` `Bilibili`/`B站` `YouTube` `媒体`（写别的平台名也能显示，只是没有专属颜色，用灰色）
- `title`：链接显示的标题文字
- `url`：真实网址，必须以 `https://`（或 `http://`）开头
- **如果暂时还没有链接**，把 `url` 留成空字符串 `""`，网站会自动显示成"待补充"的灰色占位条，不会报错，也点不出去
- **可选字段 `caption`**：比如 `"caption": "最初的MPOP"`，会在这条链接卡片正上方显示一行引用样式的小字说明，用来补充"这条为什么特殊/属于哪个阶段"之类的背景信息。不写这个字段就什么都不显示

### 4.2 分界线（`divider`）—— 比如按年份分组

```json
{ "type": "divider", "label": "2017年" }
```

直接插在 `link` 之间，网站会显示一条"2017年"的分隔线，**不会单独变成一个新的分类页面**，还是在同一页往下滚就能看到。适合"同一个分类下面按年份/按季度分组"这种情况。

> 如果一个分类下面**同时有"按年份分组的链接"和"更细的子分类（文件夹）"**，子分类那一段建议用 `{ "type": "divider", "label": "其他" }` 隔开，不要用"年份不详"——子分类本身不是"某一年发布的内容"，"其他"更准确。"年份不详"留给那些**确实查不到发布年份的单条链接**用。

### 4.3 完整事件（`event`）—— 一次舞台/作品的多条链接合集

```json
{ "type": "event", "eventId": "2025-08-01-test-stage-a" }
```

`eventId` 对应 `data/events/` 文件夹里的一个 json 文件（不带 `.json` 后缀）。这种用在"一次舞台/作品有好几个平台的好几条相关链接，想放在一起展示"的情况——具体格式见下一节。事件里每条物料（`materials` 数组里的一项）也可以加 4.1 提到的可选 `caption` 字段，用法完全一样。

### 4.4 荣誉/头衔（`honor`）—— 没有外部链接的一项荣誉

```json
{ "type": "honor", "title": "某某音乐奖·最佳男歌手", "year": 2023 }
```

用在"这是一项真实的荣誉/头衔，但没有对应的单一网页链接可以跳转"的情况（比如奖项本身）。渲染成一张**不可点击**的卡片，只显示标题和年份，旁边也不会出现点赞爱心（点赞是给"可以点开看内容"的链接/事件设计的，荣誉本身没有"内容"可看）。

## 五、常见操作怎么做

### 5.1 在某个分类下新增一条链接

1. 打开 `data/nav.json`，找到对应分类的 `children` 数组
2. 在已有的最后一项后面，先加一个英文逗号 `,`，再照着格式加一段新的：
   ```json
   { "type": "link", "platform": "微博", "title": "新的标题", "url": "https://weibo.com/新链接" }
   ```
3. 保存文件

> 最容易出错的地方就是这个逗号——每一项之间要用逗号隔开，但**最后一项后面不能有逗号**。这也是为什么更推荐让 AI 帮你改：AI 不会漏逗号。

### 5.2 修改/删除一条链接

找到对应那一项，直接改引号里的文字即可；删除就把这一整项（从 `{` 到 `}`）删掉，同样要注意处理好前后的逗号。

### 5.3 新增一条分界线（比如按年份分组）

在想分组的地方插入一项 `{ "type": "divider", "label": "2018年" }`，前后逗号处理同上。

### 5.4 新增一个更细的小分类（文件夹）

在 `children` 里加一项这样的内容：

```json
{ "id": "英文编号，不能跟别的分类重复", "title": "显示的中文名字", "children": [] }
```

以后要往这个分类里加东西，就在它的 `children` 数组里加（跟 5.1 一样）。

### 5.5 给某个分类页加一段"引言"

在这个分类节点里加一个 `"intro": "要显示的一段文字"`，会显示在这个分类页面标题下面、内容列表上面。

### 5.6 新增一个"完整事件"（多条链接合集），并挂到某个分类下

1. 在 `data/events/` 文件夹里新建一个 json 文件（文件名建议 `年-月-日-简短英文描述.json`），内容格式：
   ```json
   {
     "id": "2025-08-01-test-stage-a",
     "title": "事件标题",
     "date": "2025-08-01",
     "summary": "一两句简介",
     "materials": [
       { "category": "正式内容", "platform": "微博", "title": "链接标题", "url": "https://..." }
     ]
   }
   ```
   - `id` 要跟文件名前面那段一致
   - `date` 格式固定 `年-月-日`
   - `materials` 是这个事件下面所有的链接，每条包含 `category`（分组标题，目前用到的值：`正式内容` / `官方物料` / `当时的讨论` / `其他`，写别的文字也会自动单独成一组）、`platform`、`title`、`url`
2. 回到 `data/nav.json`，在想让这个事件出现的分类的 `children` 里加一项：
   ```json
   { "type": "event", "eventId": "刚才那个文件名（不带 .json）" }
   ```

### 5.7 修改/删除一个完整事件

修改：直接打开对应的 `data/events/xxxx.json` 文件改内容（标题/日期/简介直接改，链接的增删改跟 5.1/5.2 是同一套逻辑，只是这里字段叫 `materials` 不叫 `children`）。

删除：删掉 `data/events/xxxx.json` 这个文件，并且去 `data/nav.json` 里把引用它的那个 `{ "type": "event", "eventId": "..." }` 也删掉。

### 5.8 新增一个顶层大分类（tab），或者改配色

在 `data/nav.json` 最外层 `tabs` 数组里加一项（格式跟 5.4 一样，但通常还要加一个 `color`，比如 `"color": "#D0CBE3"`，是这个大分类卡片的背景色，浅色系比较协调）。改配色就是直接改这个 `color` 后面的色值。

### 5.9 调整顺序

`children` 数组里的顺序就是网页上显示的顺序，想调整顺序直接把整段内容剪切、粘贴到新位置就行（`data/events/` 里的完整事件，页面之间的先后顺序由各自的 `date` 字段自动决定，不是靠 nav.json 里的位置）。

### 5.10 分类卡片下面第二行显示的是什么

点开一个分类，里面每张卡片下面都有一行小字，规则是自动的，不用手动设置：

- 如果这个分类下面**包含至少一个小分类（文件夹）**，就列出这些小分类的名字（最多 4 个，超过就加"等"）——比如"舞台之神"下面显示"跨年舞台，春晚，演唱会，鸟巢 等"；如果里面还混了事件，会显示成年份（取自事件的 `date` 字段）；**混进去的单条链接不会出现在这行预览里**（不然会把某一条帖子的标题误当成分类名字显示出来，2026-09-22 修复过这个问题）
- 如果这个分类下面**完全没有小分类**（只有链接/事件/荣誉/分界线），就显示"共几项"，**分界线不算在这个数字里**（2026-09-22 修复，之前分界线也被当成一项，数字会比实际内容多）

## 六、粉丝怎么贡献链接（腾讯文档表格）

除了直接改 `data/nav.json`，还有一个更适合"很多人一起贡献链接"的办法，不需要粉丝懂 GitHub 或 JSON：

1. 让 Claude/Codex 根据当前 `data/nav.json` 生成一份 `Archive of Lay - 资料收集表.xlsx`，**每个大分类一个 sheet**，列固定是：分类路径、标题、链接、平台、年份、附注、是否文件夹链接、状态（管理员用）
2. 管理员把这份表格传到腾讯文档，分享"可编辑"链接给粉丝——腾讯文档才是长期更新的正本，本地这份 `.xlsx` 只是每次交接用的快照，不需要一直留着或者提交进这个代码仓库。粉丝往表格空行里加一行，就是加一条资料，不用碰这个代码仓库
3. **分类路径**这一列是下拉菜单，只能选表里已有的小分类，决定这条资料最终会被放进网站的哪个地方；如果确实是全新的分类，就先写在"附注"里，等导入时单独确认
4. **是否文件夹链接**选"是"，代表填的不是一条具体资料，而是一整个 B 站收藏夹/合集这样的"文件夹"链接——导入时 AI 会尝试把里面的视频一条条展开、按年份排好，跟网站上已有内容自动去重（小红书/抖音这类平台不一定能完整展开，能做多少算多少）
5. 攒了一批新内容之后，管理员把表格导出成 `.xlsx`，发给 Claude/Codex，说一声"按这个表格更新网站"——AI 只处理"状态"还没标"已导入"的新行，不需要每次把整份表格/文档从头看一遍

## 七、改完之后，网站什么时候会更新？

**你（或 AI）修改文件 → 把改动"上传"到 GitHub（这一步叫 push） → 两个部署的地方都会自动检测到变化并更新**

- **Cloudflare**（备用网址）：几十秒内自动生效
- **香港 VPS（`archiveoflay.com`，正式网址）**：服务器上有个定时任务，最多 5 分钟内自动同步

你不需要手动"发布"或"上传网站"这个动作，只需要保证修改被 push 到 GitHub 即可，两边都会自己跟上。

## 八、名词小词典

- **GitHub**：一个存放代码/资料、并记录每次修改历史的免费网站，相当于一个带"时光机"的云端文件夹
- **仓库（repository / repo）**：GitHub 上存放这个项目所有文件的地方，可以理解为"这个项目专属的文件夹"
- **commit**：一次"存档"，记录你这次改了什么
- **push**：把本地的改动"上传"到 GitHub 仓库
- **部署（deploy）**：把网站文件发布到互联网上，让别人能通过网址访问到
- **JSON**：一种数据记事本格式，用 `{ }` 表示一条记录，用 `[ ]` 表示一个列表
- **目录树 / 节点**：`data/nav.json` 里"分类套分类"的整体结构就叫目录树，里面的每一个分类或者每一条内容都叫一个"节点"

## 九、部署说明（给以后维护的人看）

网站现在**同时部署在两个地方**，push 到 GitHub 的 `main` 分支后两边都会自动更新：

- **香港 VPS（正式网址 `archiveoflay.com`）**：CMIVPS 服务器，Nginx 提供网页服务，服务器上有个每 5 分钟执行一次的定时任务自动去 GitHub 拉取最新内容。HTTPS 证书（Let's Encrypt）会自动续期，不需要人工操作
- **Cloudflare Workers（备用/对照网址）**：Dashboard 里 "Workers & Pages" 连接了这个 GitHub 仓库，push 后自动重新构建发布。仓库根目录的 `wrangler.jsonc` 是它的部署配置文件，`.assetsignore` 用来告诉它"哪些文件不要发布出去"（比如 `.git` 内部数据），一般都不需要改动

## 十、点赞（💜）功能

网站每条链接、每个分类文件夹、每个事件卡片右边都有一个紫色爱心，可以点赞：

- 空心紫色边框 = 还没点过；实心紫色 = 已经点过
- 爱心旁边的数字是**全世界所有访客共享的真实点赞总数**，不是只有你自己浏览器看到的数字
- 点赞是"顺藤摸瓜"往上算的：比如给"霸王别姬"这个事件底下的某条物料链接点赞，"霸王别姬"这个事件卡片、它所在的"跨年舞台"分类、再上一层的"综合"分类，看到的点赞数都会跟着 +1，一路加到最顶层的大 tab
- 每个分类页面（包括首页）右上角有一个"按点赞数排序"按钮，点一下能把当前页面按热度从高到低重新排列，再点一下恢复原来的顺序

这是网站目前唯一一个"动态"的部分（背后有一个很小的服务器程序配合记录点赞数），其余所有内容仍然是纯静态文件。这部分是刻意设计成**完全独立、可以随时整个撤掉**的——如果它出了故障，最坏情况就是爱心点了没反应，不会影响网站其他任何内容的正常浏览。

> ⚠️ **给以后维护/改内容的人（包括 AI）的重要提醒**：`data/events-bundle.json` 是根据 `data/events/` 文件夹自动生成的一份汇总文件，点赞的"往上汇总"和网站搜索功能都靠读这一份文件（而不是每次去读一遍 `data/events/` 里几十个文件，那样太慢）。**每次新增、修改、或删除 `data/events/` 下面的任意一个事件文件之后，都必须重新运行一次 `tools/generate-events-bundle.py`，把新生成的 `data/events-bundle.json` 一起提交**，否则点赞汇总数字和搜索结果可能会停留在旧内容上（不会报错，只是悄悄不准确）。这个坑已经真实踩过一次（2026-09-21，公益分类新增的事件点赞后没能汇总到上一层分类），后来才修复——以后改完事件文件，记得把这一步当成和"检查 JSON 逗号"同等重要的收尾动作。
